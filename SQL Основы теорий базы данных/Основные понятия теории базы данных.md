
#### Данные - это информация представленная в определенном виде в хаотичном или упорядоченном формате.

#### База данных - это совокупность данных организованных по определённым правилам, предусматривающие хранение, описание, манипулирование и удаление данных. (ячейка, место, где хранятся данные) БД

#### СУБД (система управления базой данных) - это целый комплекс программ, позволяющих создавать базу данных и манипулировать данными. 

##### Самые популярные СУБД:

- Microsoft SQL Server (MS SQL Server)
- MySQL
- Oracle 
- PostgreSQL
- MongoDB

#### SQL (язык запросов) - это специализированный язык предназначенный для работы БД.

##### Особенности SQL:

- Не является самостоятельным ЯП (нельзя написать приложение/сайт)
- Имеет чёткую структуру, близок к естественному английскому языку
- Имеет деклоративный характер (Пишем что нужно сделать, а система отделяет. При написании кода, пользователь указывает, что хочет получить, а система сама определяет, как выполнить задачу)
- Отсутствие циклов, ветвей и других привычных процедурных конструкций

##### Список диалектов языка SQL:

- T-SQL (TransactSQL) - используется в Microsoft SQL Server 
- PL/SQL (Procedural Language/SQL ) - используется в Oracle 
- SQL/PSM - используется в MySQL 
- PLpg/SQL - используется в PostgreSQL 
- Jet SQL - используется Microsoft Access 

#### Технология работы БД

- Централизованная архитектура - всё находится на одном ПК (Бухгалтер один с одного компьютера закрывает эту потребность). 
	Преимущества:
	- Легко управлять из-за нахождения всего в одном месте
	- Максимальная безопасность (всё находится на одном компьютере + сеть не нужна)
	Недостатки:
	- Колоссальная нагрузка на ПК 
	- Если сломается компьютер

- Архитектура File-Server - участвуют персональные компьютеры и выделенный сервер на котором будут храниться файлы, сервера не участвуют в обработке своих данных, они только хранят. (Файлы находятся на одном серваке, благодаря чему несколько людей могут редактировать данные, но сохраняются только последние изменения)
	Преимущества:
	- Дёшево и просто настроить, легко сделать общий доступ
	- Распределение нагрузки 
	Недостатки:
	- Огромный трафик (нагрузка на сети)
	- Конфликт (несколько людей одновременно могут редактировать один файл и сохраняется только последнее изменение)

![[Pasted image 20260908130905.png]]

- Архитектура Client-Server - это когда несколько компьютеров взаимодействуют с базой данных и получают моментальные изменения друг друга к себе на персональный компьютер и все изменения проходят через сервер (персональный компьютер отправляет запрос на сервер и получает результат обратно, как и к себе на компьютер, так этот результат приходит и другим персональным компьютерам)
	Преимущества:
	- Малая нагрузка на сеть
	- Масштабируемость
	- Центрелизованное управление (всё контралирует сервер)
	- Повышенная безопасность 
	- Снижается риск утечки данных
	- Эффективная совместная работа
	Недостатки:
	- Зависимость от сервера
	- Зависимость от сети
	- Задержка из-за удаленного сервера

- Трехзвенная архитектура (многоуровневая) - архитектура Client-Server - например, клиент выбирает пиццу и заказывает её, сервер проверяет хватает ли ингредиентов, проверяет время доставки и тд, потом сервер делает запрос в базу данных и узнаёт есть ли ингредиенты и после получения всех результатов делает ответ клиенту что заказ готовится.
	Преимущества:
	- Гибкость (можно менять приложение или сервер без замены)
	- Масштабируемость 
	- Снижение требований пк клиента 
	- Повышенная отказоустойчивость  
	Недостатки:
	- Очень сложная разработка (наладить всё между собой)
	- Задержка ответа по сети 
	- Большие затраты на обслуживание

### Модели Базы данных 

Модель базы данных - это способ структурирования данных и описания взаимосвязей между ними

1) Файловая модель - состоит из поля записей файлов. Нет связи между файлами. Данные хаотично расположены 
2) Иерархическая модель - появились связи (родитель - потомок), у родителей много потомков, а у потомков только один родитель.
3) Сетевая модель - развитие иерархической, позволяет описывать более сложные взаимосвязи между данными. Проявляется связь многого ко многому 
4) Реляционная модель - самая популярная, данные предоставляются в виде таблиц, в этой модели присутствуют связи один к одному, один к многому, многое ко многому. Множество таблиц, где данные структурно расположены + они могут обращаться друг к другу из разных таблиц (условно таблицы: преподаватели, студенты и аудитория связываются)
5) Гибридная модель (Объектно-реляционной моделью)

### Основные понятия реляционной модели 

1)  Сущность (таблица) - представление набора реальных или абстрактных объектов, которые имеют  общие характеристики 
2) Атрибут (подзаголовок столбца) - именование характеристик, является частью сущности
3) Кортеж (одна строка) - это каждая строка сущности, в которой хранятся данные разных типов 
4) Связь - некая взаимосвязь между двумя сущностями

### Виды связей

1) Один к одному (один-один) - редкая, одна запись из главной таблицы соответствует только одной записи из другой таблицы
2) Один к многому (один-к-n) - популярная, одна запись из главной таблицы соответствует 0, 1 или нескольким записям второй таблицы (куриная лапа, от одной записи идёт раздвоение, растроение)
3) Многое ко многому (n-к-n) - куриная лапа с двух строн, часто используемая, но самая сложная связь, 0, 1 или много записей из главной таблицы может соответствовать 0, 1 или многим записям из другой таблицы

Первичный ключ (уникальный ключ) - уникальное поле, которое идентифицирует каждый кортеж сущности (уникальный адрес для каждой строчки)

Вторичный ключ (внешний ключ) - это столбец или набор столбцов в одной таблице, которые ссылаются на первичный ключ в главной таблице
